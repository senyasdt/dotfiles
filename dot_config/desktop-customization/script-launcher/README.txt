Установка из dotfiles: provision/windows/restore.ps1 и desktop.ps1, инструкция provision/windows/README.md. Они создают один Desktop Session.lnk. Manage.ps1 Install ниже предназначен только для отдельной установки запускатора; не добавляйте его параллельно Desktop Session.

Общий запускатель AHK

Настройки: config.json. Изменения подхватываются автоматически, обычно за секунду.
В YASB верхний виджет AHK ON/OFF — общий переключатель без счётчика процессов.
ЛКМ: всё выключить / включить все настроенные скрипты. ПКМ: всё выключить.
Подробное управление отдельными скриптами и отладка: ↻ → AHK.
Старое меню A в MyFinder относится к архивному интерфейсу.

Команда ScriptLauncher.exe --toggle-global переключает выбор атомарно внутри
существующего процесса запускатора, без PowerShell и дополнительного демона.
Из частично включённого набора первый клик выключает всё, следующий включает
весь настроенный набор. Общая пауза снимается при включении. enabled:false в
конфиге, игровые блокировки и задержка после игры сохраняют приоритет.
globalEnabled в runtime/status.json означает разрешение запуска, а не количество
процессов: во время игры виджет остаётся ON, но скрипты заблокированы.

КАК УСТРОЕН КОНФИГ

groups — именованные группы. Имя (например desktop) служит подписью.
Внутри группы два списка:
  scripts — пути к AHK-скриптам;
  closeWhileRunning — программы, при работе которых эти скрипты выключены.

Сейчас в desktop находятся:
  creative_macropad.ahk — рабочие макросы;
  mydockfinder-hotkeys.ahk — одиночный Win открывает Launchpad;
  zmk-text-replacements.ahk — текстовые подстановки.
Все три выключаются для Apex и Battlefield 6, включая их ранние запускатели.

Программу можно указать именем процесса (bf6.exe) или полным путём.
Имя процесса действует независимо от папки. Полный путь действует только
для этого файла — это важно для общих запускателей разных игр EA.
Поддерживаются переменные %USERPROFILE% и %ProgramFiles% в путях.

Дополнительная группа выглядит так (добавляется рядом с desktop):
  "another-rule": {
    "scripts": ["%USERPROFILE%\\.config\\autohotkey\\creative_macropad.ahk"],
    "closeWhileRunning": ["SomeProgram.exe"]
  }

Один скрипт можно перечислить в нескольких группах: копии процесса не создаются.
Условия объединяются. Он включится после закрытия ВСЕХ относящихся к нему
программ, даже если они описаны в разных группах.

Если нужны особые настройки, вместо строки с путём допустим объект:
  {
    "path": "%USERPROFILE%\\.config\\autohotkey\\example.ahk",
    "enabled": true,
    "interpreter": "%ProgramFiles%\\AutoHotkey\\v2\\AutoHotkey64.exe",
    "arguments": ["argument with spaces"]
  }
interpreter и arguments необязательны. enabled:false запрещает запуск скрипта.
Повторные определения одного пути должны иметь одинаковые настройки.
Для отключения группы целиком добавьте в неё "enabled": false.
Удаление скрипта из всех активных групп останавливает его и убирает из управления.

ПОВЕДЕНИЕ

При входе в Windows запускаются настроенные скрипты, если они разрешены.
Пока открыта блокирующая программа, нужные процессы AHK полностью завершаются.
После закрытия последней программы выдерживается resumeDelaySeconds (сейчас 15).
Повторное открытие программы сбрасывает отсчёт. Задержка ведётся отдельно
для каждого скрипта: разные группы могут возобновляться независимо.

Ручное выключение через ↻ → AHK сохраняется после игры и перезапуска помощника.
Если закрыть сам AHK-скрипт через его меню, запускатель также оставит его
выключенным. Включить его обратно можно через ↻ → AHK или общим переключателем.
Скрипт, завершившийся уже после успешного запуска, также остаётся выключенным;
ошибки первоначального запуска повторяются с увеличивающейся паузой до 60 секунд.

Закрытие помощника виджетов не выключает запускатель: управление скриптами
и правила для игр продолжают работать независимо от панели.

Неперечисленные в конфиге AHK-скрипты не останавливаются. Их количество есть
в runtime/status.json. Чтобы такой скрипт тоже закрывался для игры, добавьте его в группу.
Произвольно переименованные скомпилированные AHK-программы не распознаются.

Это наблюдение за процессами с интервалом pollIntervalMs (сейчас 1000 мс).
Абсолютной гарантии выключения ДО первой проверки античита нет. Полные пути
ранних запускателей уменьшают задержку. При предупреждении античита дождитесь
отключения AHK и повторите запуск игры.

При ошибке редактирования JSON продолжают действовать последние верные
правила остановки, но новые запуски приостанавливаются до исправления файла.

УПРАВЛЕНИЕ И ФАЙЛЫ

Меню A: отдельное включение/выключение каждого скрипта, общие кнопки и конфиг.
Из PowerShell в этой папке:
  .\Manage.ps1 -Action Status
  .\Manage.ps1 -Action Enable  -Script creative_macropad.ahk
  .\Manage.ps1 -Action Disable -Script creative_macropad.ahk
  .\Manage.ps1 -Action Restart -Script all
  .\Manage.ps1 -Action Stop       остановить только запускатель, оставив скрипты
  .\Manage.ps1 -Action Start
  .\Manage.ps1 -Action Uninstall  убрать свой автозапуск и остановить запускатель

runtime\state.json — сохранённое ручное состояние; не редактируйте при работе.
runtime\status.json — фактическое состояние и причины блокировки.
runtime\events.log — журнал с ограничением размера.
backup — исходные файлы автозапуска, команды и экспорт задач Windows.

Старая папка ahk-program-guard сохранена для отката; активный конфиг теперь
только этот config.json. Прежний PowerShell-помощник больше не нужен.
Не перемещайте папку, пока автозапуск включён.

СБОРКА И ПРОВЕРКА

Исходник: ScriptLauncher.cs. Требуется встроенный .NET Framework Windows.
Manage.ps1 -Action Build пересобирает помощник, не закрывая сами AHK-скрипты.
LauncherTests.cs — проверки логики групп и состояний.
Test-Integration.ps1 — проверка на временных безобидных скриптах и процессах;
исходный конфиг возвращается автоматически. Игры для проверки не запускаются.
