# Лента независимых колонок komorebi

27 октября 2026, HOMEPC. Включена отдельная экспериментальная сборка на базе
установленной версии 0.1.41. На пространстве 1 — Scrolling с независимыми
ширинами, на 2–9 — BSP. Владелец подтвердил нужное поведение ширины и прокрутки;
настройка 90 ms заметно улучшила плавность по подтверждению владельца. Вертикальные группы отложены по просьбе владельца.

## Управление

- Alt+1 — перейти к ленте. Alt+колёсико — соседнее окно; лента прокручивается,
  когда выбранное окно выходит за видимую область. Обычное колесо работает в приложении.
- Тянуть боковую границу мышью — менять ширину одной колонки. Остальные
  сдвигаются вдоль полосы, сохраняя свою ширину. Вся полоса не обязана помещаться на экран.
- Alt+плюс/минус — ширина; Alt+Shift+H/L — порядок колонок.
- Alt+Shift+F — monocle и обратно; Alt+T — floating. F-клавиши не менялись.

Начальная ширина — половина рабочей области, дополнительные боковые поля отключены (Peek=0). Это стартовая
ширина, а не ограничение в два окна. Существующие ручные resize_dimensions
сохранены. Окно шире видимой области при фокусировке выравнивается по левому краю.
Обычные ограничения минимального размера приложения продолжают действовать.
Пункты «Одно/два окна» в ↻ меняют базовую ширину ВСЕЙ ленты; для отдельного окна
нужны мышь или Alt+плюс/минус. Эти пресеты не заменяют независимое изменение размера.

## Включить и вернуть

- `Independent-Columns.cmd` — включить независимые колонки.
- `Stock-Komorebi.cmd` — вернуть штатные бинарники Scoop, в том числе если
  экспериментальный daemon уже завершился. Окна остаются открыты.
- `BSP.cmd` — вернуть BSP на текущем пространстве и прежние эффективные
  боковые отступы. Это смена раскладки; сама сборка остаётся экспериментальной.

При смене сборки перезапускаются komorebi и whkd через существующий запускатор.
Используется штатное восстановление сессии: окна сохраняют пространства;
точное размещение в пикселях не обещается. YASB, DesktopBridge и ScriptLauncher
не перезапускаются. AHK не включаются, игровые правила и ручные состояния сохраняются.

`Start-DesktopWM.ps1` замечает `runtime/native-profile.json`. Пока флаг включён,
рестарт из ↻ и обычный автозапуск используют ту же экспериментальную сборку.
Без флага действует прежний Scoop и основной `~/komorebi.json`. `Stock-Komorebi.cmd`
удаляет только этот локальный флаг; при неудаче возврата он не включается обратно.
Не нажимать Apply/Restore темы ради смены раскладки. Git-ветка сама рабочий стол не переключает.

## Что изменено и как сопровождать

Программных плагинов для замены алгоритма раскладки не использовано. Пользовательские
JSON-раскладки komorebi описывают структуру, а не новый динамический движок ленты.
Вместо самостоятельного большого форка — закреплённая база и два патча:

1. База `v0.1.41`, commit `24c0ce0b1df1b5d7d62c682a7e28b32980293883`.
2. [Upstream PR #1754](https://github.com/LGUG2Z/komorebi/pull/1754), commit
   `0fbe6f6a8b89b0b263cfec476dd940a8364f85dc`: независимые ширины,
   накопленные позиции колонок и viewport по фактическим размерам. PR пока не merged.
3. Локальный небольшой фикс: горизонтальный resize первой, последней и единственной
   колонки без проверки наличия соседа; ширина не ограничена одним viewport.
   Фикс работает только при `fixed_column_width=true`; BSP и обычный Scrolling
   сохраняют прежний путь. Защитные границы content width — 64…32767 px.

Патчи с авторством и SHA256 находятся в `native/`. `native/Build-Native.ps1`
проверяет их хэши, точный commit базы, применение, тесты и собирает два exe.
Нужны Windows Rust/MSVC 1.99.1 и Visual Studio C++ Build Tools. На новой машине
сначала восстановить штатное окружение; эта сборка — отдельный необязательный шаг.

```powershell
.\native\Build-Native.ps1 -BuildDirectory C:\Temp\komorebi-independent-build
.\Use-Native.ps1 -Mode Independent -WhatIf
.\Use-Native.ps1 -Mode Stable
```

BuildDirectory должен отсутствовать. Скрипт никогда не сбрасывает существующий checkout.
Проверенный результат появляется в новом `runtime/bundle-*`; сохранить прежний
`runtime/native`, затем при выключенной экспериментальной сборке скопировать туда
exe и build-info.json из нового bundle. Хэши проверяются перед запуском.
Большой локальный checkout `WorkingFolder/komorebi-scrolling-build` не нужен для
восстановления: необходимые изменения записаны отдельными patch-файлами в dotfiles.

Обновление komorebi не означает автоматический перенос патча на новую базу:
при смене версии нужно проверить diff и тесты. При конфликте сборка останавливается.
Если возможность войдёт в официальный релиз, перейти на него и убрать ставшие
ненужными патчи. Автосборок, новых фоновых служб и новых AHK здесь нет.

## Локальные данные и проверка

`runtime/native/` — бинарники и build-info с хэшами; `runtime/native-config.json`
генерируется из основного конфига, не заменяя его; `before-native-*.json` — локальные
снимки перед переключением. Они могут содержать заголовки окон и исключены из Git
и chezmoi вместе со всем runtime. `runtime/layout-offsets.json` сохраняет прежние
эффективные отступы для BSP; унаследованный null CLI возвращает как эквивалентный Rect.

Проверено: 147 тестов раскладок; release-сборка обоих exe; точное воспроизведение
Git tree из двух сохранённых патчей; WhatIf без переключения; реальная смена
штатная → экспериментальная → штатная → экспериментальная. Все шесть исходных
окон сохранили пространства. При увеличении первой колонки на 50 px ширины трёх
соседей изменились на 0/0/0; обратная команда вернула исходные ширины.
Владелец подтвердил поведение мышью и прокрутку, затем сообщил о рывках.
После настройки 90 ms/ease-out-sine/60 fps подтвердил: «Да, заметно лучше».

Плавность — отдельная проверка. Первоначально были movement 160 ms/ease-out-cubic/60 fps
и шаг колеса не чаще 120 ms. Оставлены 90 ms/ease-out-sine/60 fps, чтобы
движение завершалось между шагами; экран сообщает 59 Hz. Причина всех рывков
пока не установлена; vsync-синхронизация и плавность как у macOS не обещаются.
`Set-Motion.ps1 -Mode Smooth/Instant` управляет общей movement-анимацией сессии,
включая BSP; точные чужие временные параметры CLI не экспортирует.

Несколько мониторов, вертикальные группы и реальные игры в этой пробе не проверялись.
Новый режим ограничен одним монитором. Прежний mouse hook продолжает работать
в существующем DesktopBridge только в Scrolling, без полноэкранного окна/monocle,
при живом игровом guard без блокировок; в BSP hook снимается. Это не тест античита.
