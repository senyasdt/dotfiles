# Горизонтальный Scrolling: проба на потом

Подготовлено 24 октября 2026 года для HOMEPC, komorebi 0.1.41.
Ветка dotfiles `komorebi-scrolling` ответвлена от `yasb-catppuccin` (`593f303`).
Scrolling пока **не включали**: активные и сохранённые девять пространств — BSP.
YASB, whkd, автозапуск, AHK game rules и библиотека Alt+F12 не менялись.

## Как попробовать и вернуть

1. Перейти на нужное пространство, например Alt+9 для отдельной пробы.
2. Запустить `Scrolling.cmd` из этой папки. Меняется только это пространство:
   горизонтальная лента с двумя видимыми колонками. Открыть несколько окон,
   закрыть окно Проводника/терминала, если оно мешает оценке.
3. Alt+H / Alt+L — переход между окнами влево/вправо; Alt+Shift+H/L — перемещение
   окна. Alt+1…9 — прежнее переключение пространств. Визуальное поведение этих
   действий в Scrolling ещё предстоит проверить на твоих приложениях.
4. На том же пространстве запустить `BSP.cmd` — вернуть BSP без перезапуска
   менеджера, темы или AHK. Повторить для каждого пространства, где пробовал.

Можно закрепить папку в быстром доступе Проводника или создать ярлыки на эти два
файла в меню «Пуск». Автозапуск и новые горячие клавиши намеренно не добавлялись.
`Status.cmd` показывает текущие монитор, пространство и раскладку.
Скрипты не закрывают приложения; восстановление прежнего расположения каждого
окна пиксель в пиксель не обещается — BSP пересчитает размещение.

## Терминал и проверка без применения

Из PowerShell в этой папке:

```powershell
.\Switch-Layout.ps1 -Mode Scrolling -WhatIf
.\Switch-Layout.ps1 -Mode Scrolling -Columns 2
.\Switch-Layout.ps1 -Mode Bsp
.\Switch-Layout.ps1 -Mode Status
```

`-WhatIf` читает состояние и показывает план без изменения раскладки.
Команды используют действующую пользовательскую сессию и установленный
komorebic; права администратора, отдельный WM и AHK им не нужны.
При ошибке IPC скрипт останавливается: не трогает runtime junction и процессы.
При нескольких мониторах включение Scrolling блокируется; возврат BSP доступен.
Сначала закончить тест и вернуть BSP, затем подключать дополнительный монитор.

## Что сохраняется

Переключение временное: `komorebi.json` остаётся с девятью BSP. Перезагрузка
конфига (Alt+Shift+O) или перезапуск менеджера должны снова применить сохранённый
BSP. Для обычного возврата удобнее `BSP.cmd`; откат всей темы не требуется.
Не нажимать Apply/Restore темы ради смены раскладки.

Ветка Git хранит код, **сама по себе не переключает рабочий стол**.
Исходники: `dot_config/desktop-customization/komorebi-scrolling/` в dotfiles;
chezmoi включает папку только в Windows desktop-профиле. На новой машине после
просмотра diff можно применить только эту папку; глобальный apply ради неё
не нужен. Постоянный Scrolling и меню выбора в YASB — следующий этап после
ручной пробы. Нынешний BSP-виджет YASB не является новым переключателем:
его прежний клик monocle сохранён, отдельная иконка Scrolling ещё не добавлена.

## Проверено и ограничения

Проверены наличие CLI-команд в установленной версии, синтаксис PowerShell,
чтение состояния и план `-WhatIf`. В момент подготовки: один монитор, девять BSP.
Реальное включение Scrolling, плавность, разные приложения, fullscreen и
поведение дока в этой раскладке **не испытывались**. Это подготовленный
переключатель для будущей пробы, а не заявление о стабильности нового режима.

Встроенный Scrolling — горизонтальная раскладка komorebi, не полная копия niri
с его жестами и обзором. Другие менеджеры пока не устанавливались.
