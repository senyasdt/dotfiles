# YASB · холодная серая полупрозрачная палитра

**Актуальная основная схема HOMEPC с 28 октября 2026: LeopardWM + YASB.**
Ветка `leopardwm-test`; [настройка, автозапуск и возврат](../leopardwm-test/README.md).
Панель показывает `LWM · N`, ЛКМ открывает обзор; ↻ → LeopardWM управляет
выбранным менеджером. Обновление темы сохраняет этот адаптер. Komorebi остаётся
запасным, его подписка и hook колеса при LeopardWM отключены. Перед полным
возвратом старой темы сначала выбрать komorebi. Ниже сохранены описание базового
профиля и датированная история проверок на komorebi.

Опциональный Windows desktop-профиль, ветка `yasb-catppuccin`. Требует YASB
2.0.7 или новее; схема 2.0.7 проверена 25 октября 2026 года. Первоначальная
живая проверка: YASB 2.0.0 / CLI 1.1.7 и komorebi 0.1.41, HOMEPC 24 октября.
Оформление вдохновлено [Villoh — Win11 Catppuccin Edition](https://www.reddit.com/r/desktops/comments/1rvjrok/win11_catppuccin_edition/).
Требования владельца взяты из обсуждения и
[общего чата](https://chatgpt.com/share/6adc0b89-947c-83eb-94a2-2db9fe41c81e).

## Целевая схема

YASB + штатный komorebi/whkd + ScriptLauncher. MyDockFinder больше не является
вариантом установки или автозапуска; FinderWidgets не разворачивается на новой
машине. Упоминания MyDock ниже относятся только к историческим снимкам отката.
Имя mydockfinder-hotkeys.ahk сохранено для совместимости правил и ручных состояний
AHK; сам скрипт не требует и не запускает MyDockFinder.
Название профиля catppuccin сохраняется, текущая палитра — Cold Grey.

## Что включено

- Верхняя панель в нейтральной серой гамме с приглушёнными голубыми акцентами: девять пространств komorebi, BSP/monocle, активное окно,
  часы, музыка, VPN, Vial/ZMK, AHK, раскладка, погода, звук, трей, меню профиля.
- Нижний док: библиотека приложений, поиск внутри Launchpad и открытые окна.
  Приложения закрепляет владелец через ПКМ → Pin to taskbar. ЛКМ переключает окно,
  ПКМ открывает меню, наведение — preview. Фиксированных ярлыков нет.
- Launchpad с поиском: импорт Start Menu + AppsFolder, включая packaged apps.
  Импортер извлекает существующие значки Windows; private каталог не хранится в Git.
- Alt+F12 регистрирует сам YASB. Одиночный Win вызывает тот же shortcut через
  управляемый AHK; сочетания Win+E и другие сохраняют прежнюю логику Win-tap.
  Когда правила игры закрыли AHK, доступны мышь и родной Alt+F12 YASB.
- AHK ON/OFF: ЛКМ переключает «всё выключено / включить все настроенные скрипты»,
  ПКМ выключает все. Отдельные скрипты, исключения и отладка — только в ↻ → AHK.
  ON означает разрешение запуска: игровые блокировки и задержка возобновления
  продолжают действовать. Счётчика процессов и списка скриптов в подсказке нет.
  Команда `--toggle-global` выполняется внутри существующего ScriptLauncher,
  атомарно по его текущему состоянию; быстрые клики не читают устаревший status.json.
  Vial: ЛКМ открывает прежний overlay; ZMK: ЛКМ открывает папку данных.
  VPN: ЛКМ добавляет/проверяет домен, ПКМ проверяет домен из буфера.
- `…` вверху: системная библиотека и настройки Windows.

Это оформление YASB. Тема Explorer, темы приложений, wallpaper и системные
патчи Windows этим профилем не устанавливаются. komorebi/whkd, HID-прошивки,
текущая IPC junction и правила игр не заменяются.

## Быстрый возврат

Запускать обычным пользователем, администратор не нужен:

- **Restore Previous.cmd**: точный config/CSS/Win-helper/MyDock INI и прежний
  Startup из private snapshot перед экспериментом; запускает ранее работавшие
  MyDockFinder/FinderWidgets/YASB. Возвращает прежние theme/bar user env.
- **Restore Before MyDock.cmd**: прежнее расположение YASB и CSS, стандартная
  панель задач, обычный Win. Legacy кнопка рестарта теперь открывает безопасное
  современное меню помощников; старый daemon chain не возвращается. Конфиг не содержит API key.
- **Apply Catppuccin.cmd**: снова включает этот профиль, snapshot не перезаписывает.
- **Show Windows Taskbar.cmd**: останавливает помощник дока и показывает
  стандартную панель задач, оставляя верхний YASB.

Ярлыки также созданы в **Start Menu → Desktop Profiles**; рабочий стол ими не
засоряется. Файлы `private/`, `runtime/`, настройки текущего ПК и EXE не коммитятся.
Private snapshot содержит чувствительные старые настройки: хранить отдельно от Git.

На HOMEPC текущая установка находится в
`%USERPROFILE%/WorkingFolder/desktop-customization/yasb-catppuccin`.
Не удалять эту папку: оттуда работает помощник, Startup и откат. Исходники на
ветке находятся в `dot_config/desktop-customization/yasb-catppuccin`.
Старые helpers WorkingFolder и активная junction komorebi оставлены на местах.

## Новая машина / ручная установка

Нативный Windows `restore.ps1 -Profiles full,desktop -Bar yasb -Theme catppuccin`
показывает план; с `-Apply` применяет профиль после обычного восстановления.
Для существующей установки, где уже есть ScriptLauncher и YASB:

```powershell
# Из разложенной chezmoi папки .config/desktop-customization/yasb-catppuccin
Copy-Item settings.example.json settings.json
# При необходимости поправить пути существующих helpers в settings.json.
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Manage.ps1 -Action Build
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Manage.ps1 -Action Apply
```

Стандартный путь helpers — `%USERPROFILE%/.config/desktop-customization`.
Профиль требует ScriptLauncher из dotfiles, установленный YASB и Windows .NET
Framework compiler. Импортер работает через штатный Windows PowerShell 5.1,
включая вызов из PowerShell 7. Python для установки не нужен.
Нужен JetBrains Mono Nerd Font (NFP): на HOMEPC он установлен; на новом ПК
завершить font setup первого запуска YASB. Это пока ручной checkpoint.

`WINDOWS_DESKTOP_THEME=catppuccin` защищает активные config/CSS/Win-helper от
перезаписи стандартным chezmoi apply этой ветки. Их владелец — Manage.ps1;
остальные source-файлы продолжают управляться chezmoi. Проверять diff перед apply.
Если есть Desktop Session, он запускает профиль; отдельный Startup ярлык тогда
не создаётся. На текущем HOMEPC до миграции остаётся отдельный YASB Catppuccin.
Защищённая задача YASB Reborn ещё существует; single-instance исключает второй
YASB, её будущая admin cleanup — отдельный ранее подготовленный шаг.

## Как устроен док

DesktopBridge — нативный .NET helper. Получает события komorebi через отдельный
named pipe; CLI вызывается при подключении/переподключении, не в цикле.
Пустое активное пространство: док виден. Есть managed tiling/floating окна:
док скрыт, появляется у нижнего края и остаётся под мышью/при popup.
Полноэкранное активное окно скрывает док. Если komorebi недоступен, используется
проверка обычных видимых окон. Служебные unmanaged окна вне komorebi не мешают
показу на пустом пространстве; fullscreen проверяется отдельно.

Определение края/полноэкранного окна обновляется каждые 400 мс; процессы YASB и
native taskbar проверяются реже. Статус пишется при изменении или раз в 10 секунд,
лог ограничен по размеру. При нормальном выходе helper или остановке YASB
стандартная панель задач возвращается. При принудительном завершении helper
использовать rescue/rollback: произвольный crash не равен штатному выходу.

`runtime/dock-status.json`, `Manage.ps1 -Action Status` — диагностика.
`Manage.ps1 -Action ImportApps` **пересобирает** каталог из установленных приложений:
ручной порядок/группы Launchpad при этом сбрасываются. После импорта следующие
открытия Launchpad видят новый каталог. Для portable приложений добавить ярлык
в Start Menu либо добавить приложение через меню Launchpad.

## Проверка и ограничения

Проверены сборка, политика дока, JSONSchema YASB, реальные AHK/HID JSON, живое
переключение пустого/занятого пространства и оба отката. В точном откате четыре
файла совпали с SHA256 private snapshot. Все 9 BSP и исправленный IPC сохранены.
Библиотека импортировала 392 приложения; это каталог данной машины, не гарантия
полного обнаружения незарегистрированных portable EXE.

Визуальный проход, клики меню, фактическое открытие приложений из Launchpad,
новый Win-tap, проверка fullscreen/края мышью, несколько мониторов, reboot и
реальные игры не подтверждены. Computer Use не получил доступ к приложению до
тайм-аута; это не результат визуального теста. Регистрация Alt+F12 видна в логах.
Прежний Win-tap/Win+E был подтверждён владельцем до замены адресата на YASB.

27 октября 2026 на HOMEPC восстановлена погода: с разрешения владельца через
штатный VPN-клиент добавлено отдельное домашнее правило `api.open-meteo.com`.
До этого HTTPS к серверу прогнозов завершался таймаутом, а строка показывала
кеш от 22 октября. После правила получены HTTP 200 через Qt и обычный HTTPS,
сам YASB обновил кеш без перезапуска. Поиск городов был доступен и до правки.
Роутерная диагностика показывает IP в VPN-наборе, но классификатор не принимает
дополнительные действующие ip rules; сообщение unknown не равно отказу HTTPS.

На новом ПК открыть карточку погоды и выбрать город; `%LOCALAPPDATA%/YASB/weather.json`
содержит координаты и кеш и в Git не переносится. Проверить доступность
`api.open-meteo.com` (прогноз) и `geocoding-api.open-meteo.com` (поиск).
Установщик не добавляет правила домашнего роутера и не включает VPN сам.
Трей: иконки 22 px, шесть в строке; native blur, матовый нейтрально-серый
`rgba(40,43,49,80)`, без CSS/DWM обводки. Размеры и spacing от предыдущей
компактной настройки сохранены.
Игровая блокировка AHK остаётся опросом процессов: не обещает успеть до первой
проверки античита. Чистая VM, повторный restore и вход после reboot ещё нужны,
прежде чем считать весь Windows recovery полностью проверенным.

Quick Launch не включён: в установленной версии наблюдались частые перестроения
его индекса при изменениях Windows Packages. Поиск находится в Launchpad;
отдельный индексатор для него не нужен.

## Виджет ↻: управление помощниками

Слева от языка, рядом с AHK: ЛКМ — общий перезапуск, ПКМ — меню. Есть общий
запуск/остановка/перезапуск, отдельные действия выбранного WM, AHK, Vial/ZMK
и безопасное открытие Vial. Управление отдельными AHK и их правилами находится
в подменю AHK. YASB продолжает работать.

Очистка 28 октября: одна группа «LeopardWM»/«Komorebi» показывает актуальные
команды запуска/остановки/перезапуска. В ней остаётся только переход к другому
менеджеру, а у LeopardWM — обзор пространств. Убраны группа ChatGPT с тестовым
отключением GPU, эксперименты с лентой и дублирующие группы WM. Восстановление
отрисовки ChatGPT остаётся отдельной командой. Из `…` убраны возвраты к старым
темам и MyDockFinder. Отдельные rollback-файлы, снимки и диагностические скрипты
сохраняются; они не предлагаются как повседневные настройки. Новые действия
WM называются `WmStart/Stop/Restart`; прежние `Komorebi*` остаются совместимыми
алиасами Services.ps1 для старых вызовов. Игровые правила AHK не менялись.

ПКМ по ↻ → «Восстановить отрисовку ChatGPT» убирает пустую полосу над меню
посредством пересоздания только GPU-подпроцесса. Repair-ChatGPTRendering.ps1
проверяет официальную Store-установку, Windows-сессию, путь, родителя, точный
аргумент --type=gpu-process и время запуска, затем ждёт новый GPU с тем же
основным PID и HWND. Если выбор неоднозначен, ничего не завершает. Основное
окно и чат остаются открыты; возможна короткая перерисовка. Это ручная команда,
она не входит в RestartAll и не создаёт фонового наблюдателя.
Для диагностики: Repair-ChatGPTRendering.ps1 -Inspect; план без выполнения:
Services.ps1 -Action ChatGPTRender -WhatIf. Причина повторения дефекта неизвестна.

Контроллер Services.ps1 запускается только по нажатию, сериализует действия и
проверяет путь процесса и Windows-сессию. Постоянного нового процесса нет.
Использует ScriptLauncher, Start-DesktopWM.ps1 и установленные HID exe напрямую;
не вызывает прежние start-daemons.cmd, Startup wrappers, FinderWidgets и taskkill.
Для HOMEPC komorebiSupportRoot в приватном settings.json указывает на текущий
WorkingFolder/desktop-customization/komorebi-support; на новом ПК по умолчанию
используется .config/desktop-customization/komorebi-support. IPC junction не менять.

Общая остановка ставит AHK на сохраняемую паузу, оставляя guard работающим.
Общий запуск снимает эту паузу, не включает вручную выключенные скрипты.
Перезапуск также сохраняет паузу/выбор. Отдельное «Включить все скрипты» —
явное включение всех настроенных AHK. Игровые блокировки и resume delay имеют
приоритет во всех этих случаях. В AHK-меню есть снятие общей паузы.

Безопасный Vial launcher принадлежит .config/vial/scripts/open_vial_safely.ps1:
закрывает только свой HID helper, ждёт выхода из редактора и возвращает helper
только если он был включён. Повторный запуск редактора блокируется. Пока редактор
открыт, меню не запускает конкурирующий Vial helper. Защищённые старые scheduled
задачи не перенастраиваются: их отдельная cleanup остаётся прежней задачей.

Обновить только активные виджеты: Manage.ps1 -Action Refresh. Команда не меняет
автозапуск, библиотеку, Win helper, AHK-правила и первоначальный snapshot.
Services.ps1 -Action Status читает счётчики, -Action RestartAll -WhatIf показывает
план без выполнения. Start/Restart komorebi — перезапуск менеджера, в отличие от
быстрой смены раскладки: временный Scrolling сбросится к сохранённому конфигу.

## Холодное оформление, 24 октября 2026

Верхняя панель снова ближе к прежнему YASB: Segoe UI 13 px, компактные отступы,
часы/пространства/BSP в центре, активное окно слева. Нейтральный графитовый фон,
серый текст и приглушённые голубые акценты без бирюзового оттенка. Та же палитра применяется
к доку, библиотеке, popup и native меню ↻/AHK. Красноватый цвет оставлен для
питания как смысловой акцент. Набор виджетов, callbacks, AHK rules, библиотека
и скрытие дока не менялись. Название профиля/ветки yasb-catppuccin сохранено
для совместимости с установкой и откатами. styles-predock.css остаётся историческим.

24 октября по уточнению владельца возвращена выраженная прозрачность: верхняя
панель имеет 25% непрозрачности фона, док 50%, Qt popup около 75%; blur включён у верхней панели и popup,
нижняя группа использует только полупрозрачность. По уточнению владельца палитра стала серее; компактная компоновка сохранена.
Native popup имеет opacity 0.94; его кратковременная проверка закрытия учитывает
быстрые полные клики/Esc между отсчётами таймера. Это не глобальный input hook.

Трей увеличен до 28 px, popup — шесть колонок с отдельными крупными областями
нажатия. С 26 октября док — родная панель YASB с width: auto и прямыми
Launchpad/Taskbar без Grouper. Фон рисует сама компактная панель; DWM blur
выключен. Bridge распознаёт и узкую панель с одной библиотекой.
Taskbar остаётся активным и при пустом списке; скрытие всего дока по-прежнему
выполняет DesktopBridge. На занятом пространстве reveal — вдоль нижнего края
экрана, на пустом пространстве панель видна постоянно.
Фиксированные ярлыки Проводника и Терминала удалены 26 октября: они не
поддерживали штатное открепление. Refresh/Apply больше не готовят для них PNG.
Пользовательские закрепления и их иконки обслуживает штатный Taskbar YASB.

У библиотеки убраны дублирующие внешние контуры: системная обводка отключена,
внешний Qt popup прозрачен, фон рисует только внутренний контейнер с радиусом
8 px без рамки. Поле поиска и карточки имеют небольшие скругления без ярких
обводок; фокус поиска сохраняет тонкий серый индикатор. Blur и полупрозрачность
контейнера сохранены. Padding 25 px компенсирует удалённую рамку в 1 px.

После повторного обрезания значков убрана зависимость дока от AutoWidthManager.
Размеры кнопок окон и pinned labels ограничены под 32 px значки; Qt самостоятельно
раскладывает компактную группу при появлении/закрытии окон, не меняя размер HWND.
Скрытие на занятом пространстве и показ на пустом сохранены; вызов у края теперь
работает вдоль нижней кромки экрана. Полупрозрачный серый фон группы сохранён.
Refresh при неизменном YAML обновляет только CSS через watcher или ничего не
делает, если файлы совпали: PID YASB/bridge и рабочая область сохраняются. При
изменении YAML перезапускается YASB, bridge сохраняет PID. При полном перезапуске
YASB возможна краткая вспышка native taskbar со стороны shell; это наблюдалось
при проверке и не считается устранённым. Сам bridge возвращает Windows taskbar
после исчезновения YASB на 8–10 секунд; явная остановка bridge возвращает её сразу.

## Обновление YASB, 25 октября 2026

Конфиги активного профиля, варианта до MyDockFinder и классический chezmoi-шаблон
мигрированы на [стабильный YASB 2.0.7](https://github.com/amnweb/yasb/releases/tag/v2.0.7).
Переименованы volume_icons → icons, maximised → maximized, заменён устаревший
{volume} на {level}; удалены старые container_padding/acrylic/center.
VPN-кнопки активного профиля используют __USERPROFILE__, а не имя владельца.

## Диагностика исчезновения панели

Кнопка ↻ вызывает Services.ps1: она перезапускает помощники, оставляя YASB
работающим. Действия и отдельные шаги общего restart записываются в
runtime/services.jsonl с PID YASB/WM/bridge/guard до и после шага. Журнал
ограничен 256 KiB плюс одна предыдущая копия; Status и WhatIf его не заполняют.
Командные строки, конфиги и произвольный текст ошибок в этот журнал не пишутся.
Дополнительного фонового процесса и автоматического рестарта панели нет.

Для диагностики настоящего падения YASB 2.0.7 использовать его штатный CLI:
`yasbc enable-crash-dumps` из административной консоли. Проверить per-app key
HKLM/Software/Microsoft/Windows/Windows Error Reporting/LocalDumps/yasb.exe:
DumpCount=5, DumpType=0, CustomDumpFlags=6501; DumpFolder указывает на
~/.config/yasb/dumps. Отключение: `yasbc disable-crash-dumps` от администратора.
Дампы и логи остаются локальными, в Git/облако не загружаются; дамп может
содержать данные из памяти. На новых ПК этот диагностический режим не включён
автоматически. Лог YASB — ~/.config/yasb/yasb.log; аварии Windows — Application,
события 1000/1001. Наличие строки Windows fatal exception само по себе ещё
не доказывает завершение процесса: сверять время, PID, WER и последующие записи.
Исчезновение только нижнего дока при живом YASB проверять отдельно по
runtime/dock-status.json и состоянию komorebi. Fullscreen штатно скрывает бары.

## Повторяющаяся полоса ChatGPT: тест графического ускорения

27 октября 2026: основной процесс сохраняется при сбое отрисовки; старые
пересоздания GPU убирали полосу. В журнале приложения есть Recoverable Chromium
child process gone с processType=GPU/reason=crashed. Это также может быть запись
о ручном Kill из восстановления; по ней нельзя доказать самопроизвольный сбой
драйвера. Windows Display 4101 и свежих Application crash не найдено. Корневая
причина не установлена, аппаратное ускорение включено, установлены AMD iGPU
и NVIDIA RTX 5070 Ti. Внешние правила komorebi для снятия titlebar ChatGPT не найдены.

ПКМ ↻ → ChatGPT → «Запустить без GPU (тест)» — отдельный запуск с --disable-gpu.
Сначала самому выйти из приложения; при открытом ChatGPT помощник откажет,
ничего не закрывая. Когда запуск выполнен, проверить обычную работу и переключение
пространств: появляется ли полоса снова. Это локальная диагностическая гипотеза,
не официальный подтверждённый фикс OpenAI. Флаг найден в установленном Chromium;
тестовый запуск пока не выполнен, чтобы сохранить активный чат.

Постоянные настройки, профиль и авторизация не меняются. Откат: выйти из
тестового приложения и запустить обычно (обычный ярлык или соседний пункт меню).
Исполняемый файл каждый раз определяется по точной зарегистрированной Store
package family; путь версии не зашит. Несколько установок/одновременные старты
отвергаются. Software mode может увеличить нагрузку CPU; это временный A/B-тест.
CLI: Start-ChatGPTRenderMode.ps1 -Mode Software|Default; -Inspect только читает.

Ручное восстановление GPU пишет begin/recovered/failed в
runtime/chatgpt-render.jsonl (128 KiB + одна копия), чтобы отличать свои сбросы
от других событий приложения. Сохраняются parent/GPU PID и HWND, без содержимого
чата и текста ошибок. Автоматический сброс графики по таймеру не добавлялся.

## Переподключение komorebi без рестарта панели

YASB 2.0.7 сам пересоздаёт подписку после разрыва канала: пауза 3 секунды,
затем повтор каждые 5 секунд, пока WM недоступен. Restart в меню ↻ не должен
перезапускать YASB. 27 октября проверены быстрый restart и остановка WM более
чем на 6 секунд: подписка восстановилась, PID YASB 96676 сохранился в обоих случаях.

Ошибка `os error 10050` — отдельный случай: запуск CLI из ограниченного
контекста не имеет доступа к сокету, поэтому повторы не помогают. В живом логе
ошибка повторилась после запуска панели в 13:28; запуск из обычной сессии в
13:32 восстановил подписку. AppContainer=0 не исключает другие ограничения;
точный механизм исходного запуска не установлен.

Все запуски YASB из Manage.ps1 используют Start-Yasb.ps1: реальный LOCALAPPDATA
из Known Folder, явный каталог Scoop komorebic в начале PATH и ограниченная
3 секундами проверка IPC. Проверка выполняется до Stop-Yasb/изменения файлов.
Если контекст запрещает IPC, текущая панель остаётся работающей; запускатель
нужно вызвать из обычной Windows-сессии. Агент использует одобренный unrestricted
вызов инструмента, а не запускает GUI из sandbox. Отказ 10061 при выключенном WM
разрешён: штатный listener дождётся его возвращения. Нового фонового watchdog,
патча установленного YASB или принудительного reload при restart WM нет.

Диагностика без запуска/остановки: `powershell -NoProfile -ExecutionPolicy Bypass
-File .\Start-Yasb.ps1 -CheckOnly`. Журнал: ~/.config/yasb/yasb.log, строка
`Komorebi connected to named pipe`. Защита применяется к Manage; прямой запуск
самого yasb.exe обходит её. Новая машина/вход в систему отдельно не тестировались.
