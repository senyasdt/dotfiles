# Экспериментальный фикс custom-виджетов YASB

Ветка `dev`, только **YASB 2.0.7 x64**. Общий restore не применяет этот патч.
Меняется один модуль внутри YASB; новой службы, watchdog или постоянного
внешнего процесса нет. Оформление, AHK и менеджер окон сохраняются.

## Причина и проверки

29 октября 2026 YASB упал в Qt6Core.dll 6.10.2: `0xc0000005`, смещение
`0xeb757`, Python-стек `CustomWorker.run → self.finished.emit()`. Точный
установленный байткод воспроизвёл тот же сбой с фиктивной командой.
Исходная схема — QObject в GUI-потоке, run через короткоживущий Python Thread,
сигнал finished → deleteLater. Конкретная внутренняя гонка Qt и экземпляр
виджета ещё не установлены.

Фикс использует QThread и его штатный finished после возврата из run.
Приложение удерживает незавершённые workers; удаление виджета отменяет результат,
а выход приложения ждёт завершения. Ошибки команды перехватываются в run.
Чтение stdout через communicate и обработка str/bytes следуют текущему upstream.
Отмена сохраняет прежнюю семантику: команда не убивается. Как и прежний
non-daemon Python Thread, зависшая произвольная команда может задержать выход.
Текущие виджеты HOMEPC читают короткие локальные статусы.

Проверены JSON/text, ошибки, замена опроса, отмена, удаление виджета, выход
приложения; два прогона по 10 000 обновлений без падения и утечек workers;
настоящий CustomWidget из подготовленного frozen-архива без видимого окна.
Четыре теста архива проверяют повторную установку, обновление, точный Undo,
сохранение чужого Launchpad-патча, отказ при повреждении/параллельной замене.
Среда тестов: отдельный Python 3.14.5, установленные Qt/PyQt 6.10.2.
Долговременная стабильность пока не доказана.

## Установка и откат

Нужен Python 3.14 только для установки/отката и тестов. YASB использует свой
Python 3.14.7. Версия EXE и SHA256 оригинального custom.pyc проверяются;
неизвестная сборка не изменяется. Оригинал хранится внутри library.zip,
все остальные entries, включая расширение Launchpad, сохраняются.

Закрыть панель через `& "$env:ProgramFiles\YASB\yasbc.exe" stop`.
Из этой папки, **PowerShell администратора**:

```powershell
.\Install-CustomWorkerFix.ps1 -Action Status
.\Install-CustomWorkerFix.ps1 -Action Apply
# Быстрый возврат к исходному механизму:
.\Install-CustomWorkerFix.ps1 -Action Undo
```

После Apply/Undo запустить YASB обычным способом **от обычного пользователя**.
Установщик не останавливает/запускает приложения. Undo возвращает точный
исходный модуль. Обновление YASB может заменить патч; перенос на новую версию
требует повторной проверки. В master и komorebi эта правка не включена.

```powershell
python test_custom_worker.py
python test_custom_worker.py --shutdown
python test_custom_worker.py --stress 10000
python test_archive.py
# На копии library.zip после patch_custom_worker.py apply:
python test_frozen_widget.py --archive C:\Temp\YASB-test\library.zip
```

`test_archive.py --temp-root C:\Temp` задаёт папку временных тестовых архивов.
`reproduce_original.py --seconds 15` — опциональный тест **воспроизведения падения**
исходного байткода, максимум два логических CPU, четыре workers, низкий приоритет.
Гонка недетерминирована: отсутствие сбоя за один прогон не доказывает исправность.
На исправленной установке он читает сохранённый оригинал. Дампы не входят в Git.

## Upstream

В [текущем custom.py](https://github.com/amnweb/yasb/blob/main/src/core/widgets/yasb/custom.py)
схема QObject + threading.Thread ещё присутствует. Стоит открыть issue с
воспроизведением, затем небольшой PR о lifecycle, адаптированный к main.
Архивный установщик upstream не нужен; отдельно следует обсудить политику
зависших команд. Issue/PR из этой работы не публиковались.
