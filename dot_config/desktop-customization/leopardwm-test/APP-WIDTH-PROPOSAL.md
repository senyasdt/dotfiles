# Предложение стартовых размеров приложений

28 октября 2026, HOMEPC, LeopardWM 0.3.4. **Это предложение, не применённые
правила.** Текущие размеры, расположение открытых окон, назначения пространств
8/9 и игровые правила не менялись.

Процент означает ширину колонки относительно рабочей области. 100% сохраняет
верхнюю панель и ленту; это не fullscreen. Размер применяется при открытии нового
окна и не должен мешать последующему ручному растягиванию. Существующая сессия
LeopardWM может восстанавливать сохранённые размеры вместо стартового пресета.

Предлагаемая шкала: **38.2 / 50 / 61.8 / 80 / 100%**, неизвестное обычное окно —
61.8%. В интерфейсе ниже 38.2 и 61.8 округлены до 38 и 62. На текущем экране
2560 px это ориентировочно 970 / 1270 / 1570 / 2030 / 2540 px с учётом полей.
38+62 и 50+50 подходят для двух соседних колонок; 80 и 100 сознательно оставляют
прокрутку способом перехода к соседним окнам.

Плавающее окно сохраняет родной размер и высоту. Утилиту с фиксированным GUI
не стоит насильно превращать в узкую колонку высотой во весь монитор. Игры,
оверлеи и оболочки имеют отдельный режим, а не правило ширины 100%.

## Оболочки и фоновые компоненты

YASB, библиотеки приложений, Flow Launcher, Command Palette/PowerToys Run,
Rainmeter, MyDockFinder, системный трей, Game Bar, NVIDIA Overlay и похожие
оверлеи не должны получать ширину колонки. У некоторых есть отдельное окно
настроек, которое можно оставить плавающим по классу/заголовку.

Для LeopardWM/komorebi, ScriptLauncher, HID helpers, AHK interpreters, служб,
NVIDIA containers, Unity shader/compiler/licensing/crash helpers, WebView2,
Node/Python/Java runtimes, Redistributables, SDK, CLI-пакетов и uninstall/help/url
ярлыков правило начальной ширины не требуется. Не создавать широкое правило
на все `pythonw.exe`, `javaw.exe`, `ApplicationFrameHost.exe` или `explorer.exe`
ради одного частного окна.

62%, окно VM — 80–100%, Notion — 62–80%, Toolbox — плавающее. Ничего из этого
для проверки не запускалось и не устанавливалось.

## Как применять после выбора

1. Дополнить шириной уже существующие правила Unity/Unity Hub/Orca/Prusa/Fusion,
   сохранив пространства 8/9. Не добавлять второе правило того же exe ниже первого:
   LeopardWM использует результат первого совпадения.
2. Для новых главных окон добавить подтверждённые exe и `column_width` 0.382,
   0.5, 0.618, 0.8 или 1.0. Для широких редакторов достаточно ширины 1.0,
   без принудительного fullscreen.
3. Сохранить приоритет системных диалогов. Перед переводом утилиты в floating
   отличить её главное окно от настроек, splash, progress и дочерних окон.
4. Отдельно выбрать компактную ширину по умолчанию: предлагается 62%, а не 100%.
   Пресеты ручного изменения дополнить 80%. Не менять центровку или анимацию ради ширины.
5. Штатный reload, затем проверить новые окна по нескольким категориям;
   открытые проекты и игровые процессы для теста не закрывать.

## Объём и ограничения аудита

Собрано 1200 наблюдений: 235 uninstall-records, 388 ярлыков Пуска/рабочего стола,
355 AppsFolder entries, 107 уникальных путей работающих процессов и 115 каталогов
установки. Это **не 1200 отдельных приложений**: в данных есть версии, дубликаты,
документация, SDK, системные компоненты и старые регистрации.

Дополнительно просмотрены каталоги программ/portable на доступных фиксированных
дисках E/F/G/R; найдено 710 exe-кандидатов, большей частью TeX CLI и вспомогательных
бинарников. Для Photoshop, Clip Studio Paint, Arduino IDE, TeXstudio, AnyDesk и
других основных кандидатов прочитаны имена/метаданные exe. Файлы пользовательских
проектов не читались, приложения не запускались. Произвольно названные portable
папки вне обнаруженных мест могли остаться за пределами аудита.

Сырой inventory, полный CSV-индекс предложений/исключений и проверенные пути
хранятся локально в `leopardwm-test/runtime/app-audit-20261028/`, исключённом из
Git/chezmoi. В Git сохраняется это вручную составленное предложение. Ширины —
эргономическая отправная точка для этого экрана, а не измеренная универсальная
норма и не гарантия минимального размера конкретного приложения.

Возможность правил ширины/тайлинга/floating и разных ролей окон подтверждается
[документацией LeopardWM](https://github.com/jcardama/LeopardWM#features).
