# LeopardWM: основной менеджер окон

С 28 октября 2026 LeopardWM выбран основным на HOMEPC. `settings.json` задаёт
предпочтение `Leopard`; после установки закреплённого portable-релиза новый
автозапуск выбирает его, даже если приватного `selection.json` ещё нет.
Явный выбор через меню имеет приоритет: после `Komorebi.cmd` вход в Windows
продолжит запускать komorebi, пока снова не выбран LeopardWM. Без установленного
релиза сохраняется прежний путь komorebi для классического восстановления.
Повреждённый файл выбора вызывает ошибку, а не запуск второго менеджера.

[Согласованная схема стартовых размеров приложений](APP-WIDTH-PROPOSAL.md):
Telegram — 50%, редакторы/CAD/слайсеры — 100%, остальные — по назначению окна.
Базовая ширина 61.8%, ручные пресеты 38.2/50/61.8/80/100%. Правила внесены в config.toml.

28 октября 2026, HOMEPC. Ветка dotfiles `leopardwm-test`, основа —
`komorebi-scrolling` на commit `97e63ff`. Используется **официальный LeopardWM
0.3.4 без изменений его исходников**, portable x64. Текущий komorebi с общей
лентой 180 ms остаётся запасным. Имя ветки и каталога `leopardwm-test`
сохранено для совместимости путей. Master и стабильная интеграционная ветка не менялись.

## Переключение

- `LeopardWM.cmd` — выбрать основной менеджер. Также ↻ → «Менеджер окон» →
  «Включить LeopardWM».
- `Komorebi.cmd` — вернуть прежнюю сессию komorebi, её пространства, конфиг
  панели и ручные ширины при совпадающем порядке HWND. Также ↻ →
  «Менеджер окон» → «Переключиться на komorebi».
- Если панель недоступна: открыть Проводник, перейти в этот каталог и запустить
  `Komorebi.cmd`. Рабочий каталог HOMEPC:
  `C:\Users\druzh\WorkingFolder\desktop-customization\leopardwm-test`.
- Аварийная штатная комбинация LeopardWM: **Win+Ctrl+Esc**. Она восстанавливает
  видимость окон и останавливает LeopardWM; затем `Komorebi.cmd` возвращает менеджер.

Git checkout сам окружение не переключает. Перед переходом на другую ветку,
удалением тестового каталога или возвратом стабильных скриптов сначала выполнить
`Komorebi.cmd`. Бинарники и снимки в runtime нужны для возврата и не удаляются.

## Управление LeopardWM

| Действие | Сочетание |
|---|---|
| Предыдущее / следующее окно | Alt+колесо вверх / вниз; Alt+H / L |
| Вверх / вниз внутри колонки | Alt+K / J |
| Пространство 1–9 | Alt+1…9 |
| Перенести окно на пространство | Alt+Shift+1…9 |
| Изменить ширину одной колонки | Потянуть боковую границу мышью; Alt+минус / равно |
| Переставить колонку | Alt+Shift+H / L |
| Floating / fullscreen | Alt+T / Alt+Shift+F |
| Собрать соседа в вертикальную колонку | Ctrl+Alt+запятая / точка |
| Вынести окно в отдельную колонку | Ctrl+Alt+Shift+[ / ] |
| Переключить колонку в табы | Ctrl+Alt+T |
| Обзор пространств | Ctrl+Alt+Space; ЛКМ по LWM в YASB |
| Пауза раскладки | Ctrl+Alt+P |

F-клавиши не переназначались. Остальные штатные привязки LeopardWM сохранены;
`lwm query hotkeys` показывает эффективные сочетания и диагностику. Базовые 61.8% —
стартовая ширина неизвестного обычного окна; для приложений действуют отдельные правила.
Вся лента не обязана помещаться на экран. Боковые поля 8 px, без
дополнительного Peek; цвет рамки и табов — холодный серый. Прокрутка 200 ms,
EaseOut, штатные DWM ghost-анимации включены.

Правила запуска приложений (28 октября): OrcaSlicer (`orca-slicer.exe`),
PrusaSlicer (`prusa-slicer.exe`) и Autodesk Fusion (`Fusion360.exe`) открывают
новые главные окна на пространстве **9**; Unity Editor (`Unity.exe`) и Unity Hub
(`Unity Hub.exe`) — на **8**. Регистр имени exe не важен. Общие правила системных
диалогов имеют приоритет, поэтому файловые диалоги не превращаются в тайлы.
Правила применяются штатным `lwm reload`; уже управляемые окна не переносятся
задним числом. Для них остаётся Alt+Shift+8/9. Фоновые процессы Unity и launcher
Fusion не привязываются отдельно.

В LeopardWM **все пространства используют ленту**; BSP как в пространствах 2–9
komorebi нет. Их независимые сессии не переводятся друг в друга: при первом
запуске LeopardWM обнаруживает открытые окна в своей сессии. При возврате
komorebi читает свою сохранённую сессию. Новые/закрытые за время теста окна
могут изменить состав; старые ширины не прикладываются к другому порядку HWND.

## Что меняет переключатель

Перед первой сменой сохраняет текущий state komorebi, точный config.yaml YASB,
его DesktopBridge.exe и прежний конфиг LeopardWM, если он был. Затем останавливает
YASB/его помощник, штатно завершает komorebi и whkd, ставит тестовый конфиг
LeopardWM и запускает только выбранный WM. После запуска возвращает YASB/помощник.
На возврате сначала подтверждает завершение LeopardWM, затем запускает komorebi.
Ошибки запуска LeopardWM вызывают попытку штатного возврата; при неподтверждённой
остановке второй WM не запускается. Неизвестные владельцы процессов не закрываются.

Первичная активация допускается без запущенного komorebi: сохраняются панель и
прежний конфиг LeopardWM, а снимок сессии komorebi создаётся только при её наличии.
При ошибке возвращаются прежние файлы; komorebi запускается автоматически лишь
если он работал до переключения. На новой машине запасной komorebi берётся из
Scoop, на HOMEPC — из выбранного native-профиля.

Новые Registry Run entries, задачи, службы и AHK не создаются. Выбор записывается
в `runtime/selection.json`: существующий `Start-DesktopWM.ps1` учитывает его и
после входа/перезапуска запускает выбранный менеджер. Для возврата обычного
автозапуска достаточно `Komorebi.cmd`. На HOMEPC используется существующий
Startup `komorebi.cmd`: его историческое имя не определяет менеджер, он вызывает
общий `Start-DesktopWM.ps1`. Второй ярлык LeopardWM добавлять не нужно.
Сам LeopardWM запускается без watchdog; дополнительного supervisor нет.

Рестарт менеджера из ↻ действует на выбранный WM. Старые пункты настройки
komorebi и прямой переключатель Smooth/Strip/Restore блокируются, пока выбран
LeopardWM. Пункты старой ленты также скрыты из меню. Обновление темы через
`Manage.ps1 -Action Refresh` сохраняет `LWM · N`; общий преобразователь проверяет
структуру YAML до записи. `Build` синхронизирует новый DesktopBridge с манифестом
переключателя, чтобы возврат не подменял его устаревшей копией. Полный откат
на прежнюю тему выполняется после `Komorebi.cmd`. AHK не возобновляются и не запускаются:
ScriptLauncher и его игровые правила продолжают работать самостоятельно.
Игры Apex/BF6 исключены из тайлинга отдельными правилами LeopardWM.

В YASB штатные komorebi widgets временно заменяются одним `LWM · N`:
ЛКМ — обзор, ПКМ — меню помощников. Это тестовый адаптер, не полноценный widget
девяти кликабельных пространств. Каждые 2 секунды один короткий DesktopBridge
читает завершённый snapshot через `lwm query workspaces`, с ограничением ожидания
1.8 s. Постоянной подписки и девяти PowerShell-процессов нет. При ошибке показывает
LWM OFF. В режиме Leopard отключены подписка komorebi и наш hook Alt+колеса;
колесо обрабатывает сам LeopardWM. Автоскрытие дока использует прежний резервный
путь определения видимых окон. Библиотека приложений, оформление и другие widgets
не меняются. После возврата остаётся помощник с обоими пунктами выбора WM.
Исправление автоскрытия 28 октября: native-окно свойств ярлыка (`#32770`),
открытое из библиотеки и принадлежащее процессу YASB, ошибочно удерживало док как
меню. Теперь учитываются только видимые, не cloaked Qt popup рядом с конкретным
доком (16 px допуска); верхний трей/карточки и native-диалоги док не удерживают.
Policy tests проверяют превью у дока, native property sheet, скрытый/cloaked popup,
верхнюю карточку и popup без горизонтального пересечения. Применение требует
перезапуска только DesktopBridge; LeopardWM, панель и открытые диалоги сохраняются.
Архивные переключатели сборок komorebi могут вернуть прежний DesktopBridge
без этих пунктов; файлы LeopardWM.cmd/Komorebi.cmd остаются независимым входом.

## Воспроизвести на другой Windows x64

Сначала установить Windows desktop профиль с YASB Catppuccin и собрать его
помощники. Пока ветка не объединена, исходником должна быть именно `leopardwm-test`,
а не опубликованный master. Предварительно запускать komorebi перед LeopardWM
не требуется; provisioner пока устанавливает komorebi/whkd как запасные пакеты.
Не применять весь чужой dirty checkout. После восстановления профиля, в каталоге
`~/.config/desktop-customization/leopardwm-test`:

```powershell
.\Install-LeopardWM.ps1
.\Use-WindowManager.ps1 -Mode Leopard -WhatIf
.\LeopardWM.cmd
# Возврат:
.\Komorebi.cmd
```

Эти два явных шага установки и активации пока дополняют общий restore;
`restore.ps1` сам portable-релиз LeopardWM не скачивает. После установки и
первой активации последующие входы запускают выбранный WM автоматически.

Установщик скачивает закреплённый официальный zip, проверяет SHA256
`698e6e7346ff3ffd84aee3ebf502cf036a74d4804882758b439a820e0a5983b0`,
распаковывает в runtime, собирает DesktopBridge штатным .NET Framework CSC и
запускает его policy tests. Система и PATH не меняются. Повторное затирание
подготовленных бинарников запрещено; обновление версии — отдельная операция.
Переключатель проверяет хэши daemon/CLI/watchdog/controller до остановки UI.
Сам конфиг копируется в `%APPDATA%\leopardwm\config\config.toml`, где его ищет
официальная программа. Существующий конфиг сохраняется и возвращается.

Все exe, release.json, selection.json, журналы и before-leopard-* снимки приватные,
исключены из Git/chezmoi. State может содержать заголовки окон. Сборка исходников
LeopardWM для этой установки не требуется.

## Проверка HOMEPC

- SHA256 официального zip, версия daemon/CLI, TOML и эффективный Alt-modifier проверены.
- Controller собран, существующие policy tests прошли; предварительный WhatIf
  не меняет состояние. `lwm doctor` подтверждает рабочую сессию и config.
- Реальный запуск → возврат: восстановлены точный YAML панели, пространства,
  порядок HWND, layout/options/offsets, ручные ширины и выбранное пространство.
  Исходные exe komorebi, komorebi.json, PID ScriptLauncher и его ручной state
  остались прежними. Возврат подтверждён до повторного включения пробы.
- На первом запуске исправлено ожидание EOF у `lwm run`: daemon наследует stdout
  CLI, поэтому запрос запуска теперь без перенаправления, а readiness проверяется
  отдельным status. Первая ошибка штатно вернула komorebi и панель.
- Один монитор. Несколько мониторов переключатель пока отвергает. Doctor сообщил
  одно повышенное окно GearUP, которое обычный WM не смог принять; повышать весь
  менеджер ради него не стали. Плавность мышью, игры, сон и длительная работа
  требуют отдельной пользовательской проверки; автоматических обещаний стабильности нет.
- Перевод в основной режим: проверены resolver выбора (включая явный возврат,
  отсутствие релиза и повреждённое состояние), идемпотентная адаптация YASB,
  компиляция и policy tests контроллера. Автозапуск проверен вызовом существующего
  launcher без рестарта работающего WM. Чистая VM и фактический выход/вход в Windows
  в этой проверке не выполнялись; первичная активация без komorebi проверена по коду.
